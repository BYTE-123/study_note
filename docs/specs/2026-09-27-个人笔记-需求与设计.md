## 1. 背景（Context）

目前项目目录只提供了三份提示词、两张视觉素材与五张界面截图，尚无任何代码实现。提示词给出了功能范围与技术栈约束，截图给出了已定型的页面形态（主页、工作台、写笔记、笔记详情、AI 润色弹窗），素材给出了整体视觉基调（暖米色生活场景 + 做旧羊皮纸）。

本文档把上述零散材料固化为一份可落地实现、可验收的需求与设计契约，作为后续开发、评审与验收的唯一依据。

**现状要点：**

- 功能范围已由 `提示词/个人笔记提示词.txt` 与 `提示词/ai润色提示词.txt` 界定。
- 技术栈已锁定：前端 HTML + JS + CSS，后端 Python + Flask，数据库 SQLite。
- 两条硬性规范：错误统一返回 `{ "code", "message" }` 且前端展示中文 message；依赖使用国内镜像并锁定版本。
- 视觉形态已由截图定型，无需重新探索。

---

## 2. 目标（Goals）

- 交付一个可在公网访问、功能完整的在线个人笔记应用。
- 覆盖：主页、注册、登录、工作台、笔记管理（草稿/发布/列表/详情）、Markdown 编辑与渲染、图片上传、分享（链接 + 可选密码）、评论、收藏、个人主页、关于页。
- 提供 **AI 文本润色**：编辑器内划词 → 右键菜单「AI 润色」→ 左右对比弹窗 → 流式生成 → 确认替换选区。
- 所有界面严格落地已确认的视觉方向（暖金棕主色 + 羊皮纸质感）。
- 所有接口遵守统一响应规范，前端仅向用户展示中文 `message`。
- 代码结构清晰、分层明确，适合作为作品集展示与二次扩展。

---

## 3. 非目标（Non-Goals）

以下内容明确不在本期范围，避免范围蔓延：

- 不做富文本所见即所得编辑器（只做 Markdown 源码编辑 + 预览）。
- 不做协同编辑、实时多人同步。
- 不做移动端原生 App，仅做响应式网页。
- 不做第三方登录（微信 / GitHub OAuth）。
- 不做邮箱验证、找回密码、短信验证。
- 不做头像上传（个人主页只维护昵称与简介）。
- 不做笔记标签的独立管理页（标签仅作为笔记字段与筛选条件）。
- 不做 AI 对话、AI 摘要、AI 续写等其他 AI 能力，仅做「润色」。
- 不做评论审核、敏感词过滤、通知系统。
- 不做多语言（仅简体中文）。

## 4. 推荐方案（Recommended Approach）

**前后端分离的多页静态应用**：Flask 只提供 JSON API 与静态资源，前端为若干独立 HTML 文件，通过 `fetch` 调用接口；登录态用 Flask Session + HttpOnly Cookie；AI 润色走 DeepSeek，后端以 SSE 流式转发。

选择理由：

1. 提示词中「后端返回 `{code,message}`，前端显示 message」的规范天然指向 JSON API 形态，前后端分离与该规范最契合。
2. 多页静态 HTML 无需引入前端框架、构建工具与路由库，契合「HTML + JS + CSS」的原始约束，学习成本与依赖面最小。
3. Session + Cookie 让前端完全无需处理 token 生命周期，代码量最少。
4. SSE 相比 WebSocket 更轻、更易调试，相比轮询更实时，足以支撑「边生成边显示」的润色体验。

## 5. 备选方案对比（Alternatives Considered）

| 决策点 | 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|---|
| 前后端组织 | **前后端分离（选中）** | 与 `{code,message}` 规范契合；职责清晰 | 需自行处理登录态与跨页状态 | **采用** |
| 前后端组织 | Flask + Jinja2 服务端渲染 | 开发最快，天然携带登录态 | 与 JSON 错误规范不契合；AI 流式与局部刷新需额外绕路 | 否决 |
| 页面组织 | **多页静态 HTML（选中）** | 结构直白，无框架依赖，利于作品集阅读 | 页面间有少量重复的导航/样式 | **采用** |
| 页面组织 | 单页应用 SPA（hash 路由） | 切换无刷新 | 需自研路由与状态管理，复杂度显著上升 | 否决 |
| 登录态 | **Session + HttpOnly Cookie（选中）** | 前端零 token 处理；HttpOnly 抗 XSS 窃取 | 跨域部署时需处理 Cookie 同源 | **采用** |
| 登录态 | JWT 存 localStorage | 天然跨域 | 需前端管理 token，XSS 下更易泄露 | 否决 |
| Markdown 编辑器 | **自研轻量（textarea + 工具栏 + marked.js）（选中）** | 样式完全自控，与截图一致；依赖少 | 高级能力（拖拽、快捷键）需自行补 | **采用** |
| Markdown 编辑器 | Vditor / SimpleMDE 等库 | 功能丰富 | 样式需大量覆盖，与截图样式不符，体积大 | 否决 |
| AI 输出通道 | **SSE + fetch ReadableStream（选中）** | 轻量、实时、易调试 | `EventSource` 仅支持 GET，需改用 `fetch` 读取流 | **采用** |
| AI 输出通道 | 前端轮询任务状态 | 实现简单 | 有延迟、请求多、体验差 | 否决 |
| AI 输出通道 | WebSocket | 双向、延迟低 | 对本场景过重，需额外协议与心跳 | 否决 |
| 图片存储 | **本地磁盘 `static/uploads/`（选中）** | 无额外服务，部署简单 | 不利于多实例横向扩展（本期不涉及） | **采用** |
| 图片存储 | Base64 内嵌正文 | 无文件服务 | 正文膨胀、DB 臃肿、渲染慢 | 否决 |
| 分享页鉴权 | **静态页 + `POST /api/share/<token>` 校验密码（选中）** | 与前后端分离一致，正文不经静态文件 | 需一次额外请求 | **采用** |
| AI 服务商 | **DeepSeek（选中）** | OpenAI 兼容协议、国内可直连、成本低、中文润色佳 | 依赖第三方可用性 | **采用** |

## 6. 总体架构（Architecture）

```
┌──────────────────────────────┐
│  浏览器：静态 HTML / CSS / JS │
│  · 多页（10 个页面）           │
│  · fetch 调 JSON API          │
│  · fetch + ReadableStream 读流 │
└───────────────┬──────────────┘
                │ HTTP(S) / JSON / SSE
┌───────────────▼──────────────┐
│  Flask 应用（app.py）          │
│  · 蓝图：auth/notes/comments/  │
│    favorites/share/ai/upload  │
│  · 全局错误处理器 → 统一响应格式 │
│  · 登录校验装饰器（Session）    │
└──────┬─────────────┬─────────┘
       │             │
┌──────▼──────┐ ┌────▼──────────────┐
│ SQLite      │ │ DeepSeek API       │
│ notes.db    │ │ (OpenAI 兼容, SSE) │
└─────────────┘ └───────────────────┘
       │
┌──────▼──────────────────────┐
│ static/uploads/（本地图片）  │
└─────────────────────────────┘
```

**职责边界：**

- **前端**：只负责渲染、交互与调用接口；不含任何业务判断真值来源，一切以接口返回为准。
- **Flask 蓝图**：按领域拆分，每个蓝图只处理本领域请求，共享 `utils` 中的响应封装与鉴权装饰器。
- **models 层**：统一封装 SQLite 连接、建表、初始化与 CRUD，业务层不直接写 SQL 字符串散落各处。
- **utils 层**：统一响应（`responses.py`）与鉴权（`auth_guard.py`），是前端错误规范的唯一出口。

## 8. 数据库设计（Data Model）

### 8.1 users（用户）

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | INTEGER | PK AUTOINCREMENT | 主键 |

| created_at | TEXT | NOT NULL | 创建时间 |
| updated_at | TEXT | NOT NULL | 最后更新时间 |

### 8.3 comments（评论）

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | INTEGER | PK AUTOINCREMENT | 主键 |
| note_id | INTEGER | NOT NULL, FK→notes.id | 所属笔记 |
| user_id | INTEGER | NOT NULL, FK→users.id | 评论者 |
| content | TEXT | NOT NULL | 评论内容，最长 500 字 |
| created_at | TEXT | NOT NULL | 评论时间 |

**索引**：`idx_comments_note(note_id, created_at)`。

### 8.4 favorites（收藏）

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | INTEGER | PK AUTOINCREMENT | 主键 |
| user_id | INTEGER | NOT NULL, FK→users.id | 收藏者 |
| note_id | INTEGER | NOT NULL, FK→notes.id | 被收藏笔记（可以是自己的，也可以是他人分享的） |
| created_at | TEXT | NOT NULL | 收藏时间 |

**约束**：`UNIQUE(user_id, note_id)`。

### 8.5 级联规则

- 删除笔记 → 级联删除该笔记的 `comments` 与 `favorites`。
- 删除用户 → 本期不提供账号注销功能，暂不涉及。
- 外键约束通过 `PRAGMA foreign_keys = ON` 开启。

## 9. 接口设计（API）

### 9.1 统一响应格式

所有接口（含 AI 流式接口的错误分支）返回统一结构：

```json
{
  "code": "OK",
  "message": "操作成功",
  "data": {}
}
```

- 成功：`code = "OK"`，HTTP 200，`data` 携带业务数据。
- 失败：`code` 为语义化错误码，HTTP 状态与错误码对应，`data` 为 `null`。
- 前端**只读取并展示 `message`**，不依赖 `code` 做文案拼接。

### 9.2 错误码表

| code | HTTP | message 示例 | 触发场景 |
|---|---|---|---|
| OK | 200 | 操作成功 | 正常返回 |
| PARAM_ERROR | 400 | 参数不完整或格式错误 | 缺字段、邮箱格式错、长度超限 |
| PASSWORD_ERROR | 400 | 邮箱或密码错误 | 登录失败（不区分账号不存在） |
| WRONG_PASSWORD | 403 | 分享密码错误 | 分享页密码校验失败 |
| UNAUTHORIZED | 401 | 请先登录 | 未登录访问受保护接口 |
| FORBIDDEN | 403 | 无权操作该资源 | 操作他人笔记/评论 |
| NOT_FOUND | 404 | 资源不存在 | id 或 token 无效 |
| CONFLICT | 409 | 邮箱已被注册 / 昵称已被占用 | 唯一约束冲突 |
| FILE_ERROR | 400 | 仅支持 jpg/png/gif/webp，且不超过 5MB | 上传非法文件 |
| AI_ERROR | 502 | AI 服务暂时不可用，请稍后重试 | DeepSeek 调用失败/超时 |
| RATE_LIMIT | 429 | 操作过于频繁，请稍后再试 | 频率限制触发 |
| SERVER_ERROR | 500 | 服务器开小差了，请稍后重试 | 未捕获异常兜底 |

### 9.3 认证（auth）

| 方法 | 路径 | 鉴权 | 请求体 | 返回 data |
|---|---|---|---|---|
| POST | `/api/auth/register` | 否 | `{email, username, password, confirm_password}` | `{id, email, username}` |
| POST | `/api/auth/login` | 否 | `{email, password}` | `{id, email, username}` |
| POST | `/api/auth/logout` | 是 | — | `null` |
| GET | `/api/auth/me` | 是 | — | `{id, email, username, bio}` |

校验规则：邮箱格式合法；用户名 2–20 字符且唯一；密码 ≥6 位；`password` 与 `confirm_password` 一致。

### 9.4 笔记（notes）

| 方法 | 路径 | 鉴权 | 说明 |
|---|---|---|---|
| GET | `/api/notes` | 是 | 我的笔记列表，支持 `status=draft\|published\|all`、`keyword`、`tag`、`page`、`page_size` |
| POST | `/api/notes` | 是 | 新建笔记，体 `{title, content, tags, status}`，返回 `{id}` |
| GET | `/api/notes/<id>` | 是 | 详情（作者本人）；返回正文、状态、分享信息、是否已收藏 |
| PUT | `/api/notes/<id>` | 是 | 更新笔记，仅作者可操作 |
| DELETE | `/api/notes/<id>` | 是 | 删除笔记，仅作者可操作 |
| GET | `/api/notes/stats` | 是 | 工作台统计 `{draft, published, favorite}` |
| GET | `/api/notes/recent?limit=5` | 是 | 最近文章 `[{id, title, status, updated_at}]` |
| PUT | `/api/notes/<id>/share` | 是 | 体 `{enabled, password}`；开启时生成 token，`password` 为空表示无密码 |
| PUT | `/api/notes/<id>/comment-setting` | 是 | 体 `{enabled}`，切换评论开关 |

`GET /api/notes/<id>` 返回结构：

```json
{
  "code": "OK", "message": "操作成功",
  "data": {
    "id": 1, "title": "孙子兵法", "content": "# ...",
    "tags": "学习笔记", "status": "published",
    "is_shared": true, "share_token": "1df59a95...", "has_password": false,
    "comments_enabled": true,
    "created_at": "2026-06-17T14:33:00", "updated_at": "2026-06-17T14:35:00",
    "favorited": false, "is_owner": true
  }
}
```

`GET /api/notes` 列表项结构：`{id, title, summary, tags, status, is_shared, created_at, updated_at}`，其中 `summary` 为正文去除 Markdown 标记后的前 80 字。

### 9.5 收藏（favorites）

| 方法 | 路径 | 鉴权 | 说明 |
|---|---|---|---|
| POST | `/api/notes/<id>/favorite` | 是 | 切换收藏，返回 `{favorited: true}` |
| GET | `/api/favorites` | 是 | 收藏列表，支持分页；项含 `{note_id, title, owner, is_self, is_available, created_at}` |

`is_available` 标记被收藏笔记当前是否仍可访问（他人取消分享则为 `false`）。

### 9.6 评论（comments）

| 方法 | 路径 | 鉴权 | 说明 |
|---|---|---|---|
| GET | `/api/notes/<id>/comments` | 否 | 返回 `{comments_enabled, items:[{id, user:{id,username}, content, created_at, is_self}]}` |
| POST | `/api/notes/<id>/comments` | 是 | 体 `{content}`；评论开关关闭时返回 `FORBIDDEN` |
| DELETE | `/api/comments/<id>` | 是 | 仅评论作者本人可删除 |

### 9.7 分享（share，公开，免登录读）

| 方法 | 路径 | 鉴权 | 说明 |
|---|---|---|---|
| GET | `/api/share/<token>` | 否 | 返回元信息 `{title, author, need_password, created_at, updated_at}`，**不含正文** |
| POST | `/api/share/<token>` | 否 | 体 `{password}`（无密码可省略）→ 校验通过返回 `{id, title, content, author, created_at, updated_at, comments_enabled, favorited, is_owner}` |

说明：未登录访客可读取无密码分享的正文；设了密码则必须先 `POST` 校验成功才返回正文。返回的 `id` 供分享页调用评论与收藏接口，`favorited` 仅在已登录时有意义（未登录固定为 `false`）。

### 9.8 上传（upload）

| 方法 | 路径 | 鉴权 | 说明 |
|---|---|---|---|
| POST | `/api/upload` | 是 | `multipart/form-data`，字段名 `file`；返回 `{url: "/static/uploads/2026/09/xxxxxxxx.png"}` |

校验：扩展名白名单 `jpg/jpeg/png/gif/webp`；大小 ≤ 5MB；文件名使用随机串，保留原扩展名。

### 9.9 AI 润色（ai，流式）

| 方法 | 路径 | 鉴权 | 说明 |
|---|---|---|---|
| POST | `/api/ai/polish` | 是 | 体 `{text}`；返回 `text/event-stream` |

- 请求体 `text` 长度限制 1–2000 字，超限返回 `PARAM_ERROR`。
- 数据帧格式：`data: {"delta": "润色后的片段"}` 逐块推送；结束时发送 `data: [DONE]`。
- 出错时发送 `data: {"error": "AI 服务暂时不可用，请稍后重试"}` 并结束流。
- 后端使用 `flask.stream_with_context`，逐块转发 DeepSeek 的流式响应。
- 前端不使用 `EventSource`（仅支持 GET），而用 `fetch` + `response.body.getReader()` 解析分片。

## 10. 界面设计契约（Interface Design Contract）

### 10.1 体验目标与用户旅程

**目标用户**：需要随手记录与整理想法的个人用户；作品集的评审者/面试官。

**界面单一最重要的职责**：让「记录 → 整理 → 分享」这条链路在一屏之内清晰可循，同时用温暖的纸感视觉传达「认真对待每一段文字」的态度。

## 11. 数据流（Data Flow）

1. **页面加载** → `js/api.js` 统一封装 `request()`：自动 `credentials: 'include'`、解析 `{code,message,data}`、`code !== 'OK'` 时弹出 Toast 并 reject。
2. **登录** → `POST /api/auth/login` → 服务端写 Session → 前端跳工作台；`GET /api/auth/me` 用于判断导航显示「登录/注册」还是「个人主页/退出」。
3. **列表/详情** → 前端 fetch → 蓝图 → models 查询 SQLite → `responses.ok(data)` → 前端渲染。
4. **写作** → 编辑器持有 Markdown 源文本 → 保存时 `POST/PUT /api/notes` → 服务端落库 → 返回 id → 跳详情。
5. **插图** → 工具栏选文件 → `POST /api/upload` → 返回 URL → 在光标处插入 `![](url)`。
6. **AI 润色** → 前端 `fetch('/api/ai/polish')` 带 `{text}` → 蓝图校验登录与长度 → 以 `stream_with_context` 调 DeepSeek（`stream=True`）→ 逐块转成 `data: {"delta"}` → 前端 `ReadableStream` 解析并追加到右侧区域 → `[DONE]` 结束。
7. **分享** → 详情页开启分享 → `PUT /api/notes/<id>/share` 生成 token → 前端拼 `share.html?token=xxx` → 他人访问 → `GET /api/share/<token>` 拿元信息（判断是否需密码）→ 需要则 `POST` 校验 → 返回正文渲染。
8. **删除** → 前端二次确认 → `DELETE` → 服务端级联删评论与收藏 → 前端回列表并 Toast。

## 12. 错误处理（Error Handling）

- **统一出口**：业务层通过 `responses.fail(code, message)` 返回；异常由 Flask 全局错误处理器捕获并转成统一结构，杜绝 HTML 错误页泄漏给前端。
- **参数校验**：入口处集中校验，缺失/格式错统一返回 `PARAM_ERROR` + 具体中文提示。
- **未登录**：`auth_guard` 装饰器返回 `UNAUTHORIZED`（而非重定向），前端据此弹出登录引导或跳登录页。
- **越权**：资源不属于当前用户时返回 `FORBIDDEN`，且不泄漏资源是否存在。
- **未找到**：非法 id / 失效 token 返回 `NOT_FOUND`。
- **唯一冲突**：邮箱/昵称重复返回 `CONFLICT`。
- **上传异常**：类型或大小不合规返回 `FILE_ERROR`；磁盘写入失败返回 `SERVER_ERROR`。
- **AI 异常**：网络错误、超时（建议 30s 超时）、上游 4xx/5xx、空响应统一转 `AI_ERROR`；流式场景先输出一帧 `{"error": ...}` 再关闭流，前端展示错误并提供「重试」。
- **数据库异常**：`sqlite3.Error` 捕获后回滚并返回 `SERVER_ERROR`，日志记录原始异常。
- **前端兜底**：网络中断时 Toast 提示「网络异常，请检查连接」；所有列表失败态提供「重试」。

## 13. 安全（Security）

**信任边界**：浏览器（不可信）↔ Flask（可信）↔ SQLite（可信）↔ DeepSeek（外部，仅发送用户选中的文本）。

- **认证**：Session + `HttpOnly`、`SameSite=Lax` Cookie；`SECRET_KEY` 由环境变量提供，不硬编码。
- **授权**：所有写操作（改/删笔记、改分享、删评论、传图）均校验登录态与资源归属；读取私有笔记仅限作者本人。
- **密码**：`werkzeug.security.generate_password_hash` 存储；登录失败不区分「账号不存在」与「密码错误」，统一 `PASSWORD_ERROR`。
- **分享密码**：同样哈希存储；校验接口失败返回 `WRONG_PASSWORD`，不提示具体原因。
- **SQL 注入**：全部使用参数化查询（`?` 占位），禁止字符串拼接 SQL。
- **XSS**：Markdown 渲染使用 marked.js，并过滤原始 HTML（`sanitize`）；用户输入在插入 DOM 时使用 `textContent` 或转义，评论/标题一律转义输出。
- **CSRF**：写接口要求 `Content-Type: application/json`，配合 `SameSite=Lax`；如需更强保障，可加同源校验头。
- **文件上传**：白名单扩展名；限制 5MB；随机重命名；存储目录不执行任何脚本；不信任前端传来的文件名。
- **路径穿越**：分享 token 与上传文件名均经校验/规范化，禁止 `..` 与绝对路径。
- **密钥管理**：`DEEPSEEK_API_KEY` 仅存于服务器环境变量，绝不返回前端、不入库、不进日志。
- **AI 输入边界**：润色文本长度上限 2000 字，避免滥用与超额计费；可加简单频率限制（`RATE_LIMIT`）。
- **隐私**：分享页对无密码链接意味着「知道链接即可读」，需在开启分享时以中文提示作者此含义。

| `blueprints/notes` | 笔记 CRUD、统计、分享与评论开关 | 评论正文、收藏关系 | models、auth_guard |
| `blueprints/comments` | 评论增删查 | 笔记归属校验（由 notes 提供数据） | models、auth_guard |
| `blueprints/favorites` | 收藏切换与列表 | 笔记内容渲染 | models、auth_guard |
| `blueprints/share` | token 解析、密码校验、正文下发 | 页面渲染 | models |
| `blueprints/upload` | 文件校验与落盘、返回 URL | 图片裁剪/压缩 | 本地文件系统 |
| `blueprints/ai` | 校验、调 DeepSeek、SSE 转发 | 提示词工程之外的内容审核 | DeepSeek API、环境变量 |
| `models` | SQLite 连接、建表、CRUD | 业务规则 | SQLite |
| `utils/responses` | 统一响应结构 | 业务判断 | 无 |
| `utils/auth_guard` | 登录校验、取当前用户 | 权限的业务含义 | Session |

**外部依赖与假设：**
- DeepSeek API：假设为 OpenAI 兼容的 `/chat/completions` 接口且支持 `stream=true`，模型名通过配置项指定；需 `DEEPSEEK_API_KEY`。
- marked.js：用于 Markdown 渲染，假设可通过静态文件本地引入（不使用 CDN，避免公网不稳）。
- 前端零构建：不引入打包器，JS 以 `<script>` 直接引入。
- 依赖安装走国内镜像（如清华 TUNA），`requirements.txt` 锁定具体版本号。

## 15. 测试（Testing）

- **接口层（pytest）**：
  - 注册/登录成功与失败分支；重复邮箱/昵称返回 `CONFLICT`；未登录访问受保护接口返回 `UNAUTHORIZED`。
  - 笔记 CRUD 与越权（他人笔记返回 `FORBIDDEN`）；删除后评论与收藏级联清除。
  - 分享：开启生成 token；无密码可直接读；有密码必须校验，错误返回 `WRONG_PASSWORD`；关闭分享后 token 失效。
  - 收藏切换幂等；`is_available` 在他人取消分享后为 `false`。
  - 评论开关关闭时禁止评论；非作者删除评论返回 `FORBIDDEN`。
  - 上传：合法/非法类型、超 5MB 的边界。
  - AI：超长文本返回 `PARAM_ERROR`；上游失败转 `AI_ERROR`（用 mock 模拟）。
- **前端手测清单**：四档宽度下的页面截图核对（见 10.5）；AI 流式逐字渲染；右键菜单仅在选中文本时出现；确认替换仅替换选区；空/错/加载状态可达。
- **端到端冒烟**：注册 → 写笔记 → 发布 → 分享 → 另开无痕窗口访问分享页 → 收藏并评论 → 回个人主页确认收藏与历史。
- **安全测试**：XSS 注入 `<script>` 于标题/评论/Markdown；SQL 注入尝试；未登录直接调写接口；上传 `.php`/`.exe` 被拒。
- **回归基线**：错误提示全部为中文且来自后端 `message`。

## 16. 部署与上线（Rollout）

- 服务器：Linux + Python 3.10+；使用 `gunicorn` 托管 Flask（`--workers 2 --timeout 120`，AI 流式需较长超时）。
- 反向代理：Nginx 处理静态资源、开启 HTTPS、转发 `/api` 到 gunicorn，并关闭对 SSE 的缓冲（`proxy_buffering off`）以保证流式不卡顿。
- 数据：`notes.db` 与 `static/uploads/` 部署在持久化目录，纳入定期备份。
- 配置：`.env` 提供 `SECRET_KEY`、`DEEPSEEK_API_KEY`、`DEEPSEEK_BASE_URL`、`DEEPSEEK_MODEL`、`UPLOAD_MAX_SIZE`。
- 依赖安装：`pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple`。
- 回滚：保留上一版代码与数据库备份；数据库结构变更采用「新增字段 + 默认值」的兼容方式，避免破坏性迁移。
- 上线验收：公网域名可访问主页；注册登录可用；写笔记/发布/分享/评论/收藏全链路可用；AI 润色能流式返回。
