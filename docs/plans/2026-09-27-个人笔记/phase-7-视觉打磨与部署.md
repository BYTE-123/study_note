## Task 3: 部署配置与运行说明

**目标：** 交付可直接部署到公网服务器的配置与说明。

**文件：**
- 新建：`deploy/gunicorn.conf.py`
- 新建：`deploy/nginx.conf.example`
- 新建：`deploy/README.md`
- 修改：`requirements.txt`（新增 `gunicorn` 并锁定版本）
- 修改：`.env.example`（补全部署所需变量）
- 修改：`README.md`（补本地与线上两种运行方式）

**步骤：**
- [ ] 在 `requirements.txt` 增加 `gunicorn` 并锁定版本（安装后写回确切版本）。
- [ ] 写 `deploy/gunicorn.conf.py`：`bind="127.0.0.1:8000"`、`workers=2`、`timeout=120`（AI 流式需要较长超时）、`accesslog`/`errorlog` 输出到日志目录。
- [ ] 写 `deploy/nginx.conf.example`：静态目录 `/static/` 直接由 Nginx 服务；`/api/` 转发到 gunicorn，且专为 SSE 设置 `proxy_buffering off; proxy_read_timeout 120s;`（否则润色会一次性卡住）；HTTPS 证书配置占位说明；`client_max_body_size 6m`（略大于 5MB 上传限制）。
- [ ] 写 `deploy/README.md`：在服务器上创建虚拟环境、用清华镜像安装依赖、配置 `.env`（`SECRET_KEY`、`DEEPSEEK_API_KEY`、`DEEPSEEK_BASE_URL`、`DEEPSEEK_MODEL`）、初始化数据库、启动 gunicorn、配置 systemd 常驻、Nginx 反向代理与 HTTPS。
- [ ] 明确数据持久化与备份：`notes.db` 与 `static/uploads/` 放在持久化目录，给出备份命令示例。
- [ ] Run: 本地以 `gunicorn -c deploy/gunicorn.conf.py "app:create_app()"` 启动
  - Expected: 服务在 8000 端口正常响应 `/api/health`，页面可访问。
- [ ] Run: 本地触发一次 AI 润色（配置 Key 后）
  - Expected: 经过 gunicorn（模拟关闭缓冲）后端到前端仍为流式逐块到达，而非一次性返回。

**安全/边界说明：** `.env` 不入版本库；Nginx 仅暴露必要端口；HTTPS 强制；`SECRET_KEY` 与 DeepSeek Key 使用服务器环境变量或受限权限文件。
