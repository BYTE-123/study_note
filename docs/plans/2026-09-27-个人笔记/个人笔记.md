# 个人笔记 实施计划

**创建日期：** 2026-09-27
**状态：** In Progress
**源需求文档：** `docs/specs/2026-09-27-个人笔记-需求与设计.md`

## 概述

**目标：** 交付一个可在公网访问、前后端分离的在线个人笔记应用，覆盖注册登录、笔记管理、Markdown 编辑与渲染、图片上传、分享、评论、收藏、个人主页与 AI 流式润色。

**架构：** Flask 只提供 JSON API 与静态资源，前端为 10 个独立静态 HTML 页面，通过 `fetch` 调用接口；登录态用 Session + HttpOnly Cookie；AI 润色由后端以 SSE 流式转发 DeepSeek 响应。

**技术栈：** Python 3.10+ / Flask / SQLite（`sqlite3` 标准库 + 参数化查询）/ 原生 HTML+CSS+JS / marked.js（本地引入）/ DeepSeek OpenAI 兼容接口 / pytest / gunicorn + Nginx。

## 依赖

- **阶段顺序：** Phase 1 是所有阶段的前置；Phase 2 是 Phase 3–6 的前置（除分享页读取外均需登录）；Phase 3 是 Phase 4/6 的前置（编辑器）；Phase 4 的分享页与 Phase 5 的评论/收藏有交集，先做 Phase 4。
- **外部服务：** DeepSeek OpenAI 兼容接口，需 `DEEPSEEK_API_KEY`、`DEEPSEEK_BASE_URL`、`DEEPSEEK_MODEL`；Phase 6 前需具备可用的 Key 才能做真机联调（单测用 mock）。
- **运行环境：** Python 3.10+；开发期用 `python app.py`，线上用 gunicorn + Nginx。
- **依赖安装：** 使用清华镜像 `https://pypi.tuna.tsinghua.edu.cn/simple`；安装后把解析出的确切版本写回 `requirements.txt` 完成锁定。
- **前端零构建：** 不引入 npm/打包器，第三方 JS 直接放 `static/js/vendor/`。
- **测试工具：** pytest（后端）；前端以四档宽度手测 + 截图核对，不引入浏览器自动化（见待定决策）。

## 成功标准

- [ ] 10 个页面均可访问，视觉与素材、截图一致，四档宽度不破版。
- [ ] 全链路可用：注册 → 写笔记 → 发布 → 分享 → 访客阅读/收藏/评论 → 个人主页回看。
- [ ] AI 润色可流式返回，取消不改动、确认替换仅替换选区。
- [ ] 所有接口返回 `{code,message,data}`，前端展示的提示均来自后端中文 `message`。
- [ ] 后端 pytest 全绿，覆盖认证、越权、分享密码、评论权限、上传边界、AI 异常。
- [ ] 依赖版本已锁定、走国内镜像；全站 UTF-8。
- [ ] 安全项已验证：参数化查询、XSS 过滤、上传白名单、密钥不入前端。

## 回滚

- 本项目为全新实现，无历史数据迁移。每阶段开始前对整个项目目录做一次压缩备份（或使用版本控制记录快照）。
- 回滚方式：还原上一阶段的目录快照，并同时还原运行时数据 `notes.db` 与 `static/uploads/`（二者不在快照内时需单独备份）。
- 数据库结构在本项目内一次性建表，如后续增列，采用「新增列 + 默认值」的兼容方式，使旧数据无需迁移即可继续使用。
- 线上回滚：保留上一版代码目录与数据库备份，切换软链或回退代码目录后重启 gunicorn、重载 Nginx。
- 单个功能出问题时可临时降级：前端隐藏对应入口（如分享开关、AI 润色菜单项），后端接口保留不动，避免影响其余功能。

## 待定决策

| 待定项 | 为何可延后 | 默认实现 |
|---|---|---|
| 依赖的确切版本号 | 需在目标环境安装时确定 | 安装当日稳定版，安装后写回 `requirements.txt` 锁定 |
| DeepSeek 具体模型名 | 随官方演进 | 由 `.env` 的 `DEEPSEEK_MODEL` 指定，代码不硬编码 |
| 是否引入浏览器自动化测试 | 手测已覆盖视觉验收 | 不引入；仅在后端用 pytest，前端手测 + 截图 |
| 列表分页默认条数 | 不影响结构 | 每页 10 条，定义为 `config.PAGE_SIZE` |
| AI 频率限制具体阈值 | 不影响结构 | 单用户每分钟 10 次，超出返回 `RATE_LIMIT` |
| marked.js 版本与其 XSS 过滤方式 | 需与引入版本对应 | 使用 marked 的 `sanitize` 能力，若版本已移除则改用白名单转义后再渲染 |
